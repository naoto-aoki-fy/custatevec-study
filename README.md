# Distributed cuStateVec benchmark

Stage 1 provides a C++17/CUDA/MPI runtime, a reusable benchmark timing harness,
and an untimed small-state smoke check. `hadamard` and `measure` are explicit
placeholders for stages 2 and 3: both exit unsuccessfully without CSV output.
The common contract is recorded in [SPEC.md](SPEC.md).

## Build prerequisites

Use a 64-bit Linux environment with GNU Make, nvcc, a compatible host compiler,
CUDA, the classic cuStateVec library with distributed index-bit swap APIs, and
CUDA-aware MPI. MPI must support device-buffer communication both within and
between nodes. This baseline routes transfers through CUDA-aware MPI on both
paths; it does not require a particular rank placement or use CUDA IPC P2P
optimization. Each MPI process owns one GPU and one contiguous sub-state-vector.

Provide an **existing** configuration generated by
[nvccoptions](https://github.com/naoto-aoki-fy/nvccoptions#using-the-generated-configuration).
Its README was consulted for the Makefile design. No config.mk was supplied in
this workspace, so there was no generated configuration to inspect. The project
never generates or overwrites it and does not discover MPI wrapper flags itself.
Inspect the configuration from your target compiler/MPI environment before use.
Its `CFLAGS_VENDOR`, `LDFLAGS_VENDOR`, and `GENCODE_FLAGS` definitions are required;
any exported environment variables remain exported to build commands.

```sh
make CONFIG_MK=/path/to/config.mk CUSTATEVEC_ROOT=/path/to/cuquantum
```

Compilation and final linking both use `NVCC` (default
`nvcc --forward-unknown-to-host-compiler`), following nvccoptions' host-option
forwarding guidance. Compiler, MPI, and GPU architecture settings come from the
included configuration. Load the matching compiler environment before building.
Missing MPI headers and libraries must be resolved through that configuration,
not by substituting a separately detected wrapper.

Project and installation overrides are separate from the imported settings:

| Make variable | Default / purpose |
| --- | --- |
| `CONFIG_MK` | `config.mk`; external nvccoptions configuration |
| `NVCC` | `nvcc --forward-unknown-to-host-compiler`; CUDA compiler command |
| `PROJECT_FLAGS` | `-O3 -std=c++17` |
| `EXTRA_CPPFLAGS` | Additional preprocessor/include options |
| `EXTRA_NVCCFLAGS` | Additional nvcc options, including explicit `-Xcompiler` forwarding if needed |
| `EXTRA_LDFLAGS` | Additional link options; use `-Xlinker` for host linker options if needed |
| `CUSTATEVEC_ROOT` | `/usr/local/cuquantum` |
| `CUSTATEVEC_INCLUDEDIR` | `$(CUSTATEVEC_ROOT)/include` |
| `CUSTATEVEC_LIBDIR` | `$(CUSTATEVEC_ROOT)/lib`; set to `lib64` when appropriate |
| `CUSTATEVEC_CPPFLAGS` | Include flag from `CUSTATEVEC_INCLUDEDIR` |
| `CUSTATEVEC_LDFLAGS` | Library search path, runtime rpath, and `-lcustatevec` |

Header and nvcc presence errors have explicit messages. Compiler/linker errors
identify missing MPI/CUDA headers or libraries and incompatible APIs. For a
custom cuStateVec layout set the includedir/libdir variables; full flag overrides
must supply the corresponding include/search/link options. The dynamic loader
must also find the MPI implementation, CUDA runtime, and any communicator plugin.
`make clean` and `make help` work without configuration and never alter config.mk.

## Communicator and GPU assignment

The runtime infers the built-in Open MPI or MPICH communicator from `mpi.h`
macros. The selected cuStateVec communicator must match the application's MPI
ABI and the MPI used by the launcher. Use `--communicator openmpi` or
`--communicator mpich` for an explicit selection when headers cannot identify it.
Only select MPICH for an implementation with the compatible ABI supported by your
cuStateVec release. Use `--communicator external --communicator-library /path/to/mpicomm.so`
for other MPI implementations. Build that plugin from the samples accompanying
your cuStateVec release, against the **same MPI installation** as the application;
it wraps MPI_COMM_WORLD. Do not supply an arbitrary libmpi as an external plugin.

The optional `--communicator-library` names the library passed to
`custatevecCommunicatorCreate`. Built-in resolution/soname behavior varies by
cuStateVec release; consult the installed release's
[communicator API](https://docs.nvidia.com/cuda/cuquantum/latest/custatevec/api-reference/custatevec/index.html#custateveccommunicatorcreate).
Current documentation describes using already loaded MPI symbols for built-in
communicators. This project links the site's MPI directly through config.mk.
Newer standard-MPI-ABI communicator enums are deliberately not required by this
baseline; standard-ABI-only installations need a compatible external plugin.

Node-local rank is discovered with `MPI_Comm_split_type(MPI_COMM_TYPE_SHARED)`.
With one visible GPU a process selects visible ordinal 0. With multiple visible
GPUs it selects its node-local rank. UUIDs are exchanged within the node to reject
duplicate assignments, including duplicate assignments hidden by per-rank device
visibility. A rank count must be a power of two, and `N > log2(P)`. Rank ordering
across nodes does not need to be contiguous. Set GPU visibility through the
launcher; do not oversubscribe GPUs.

## Infrastructure smoke check

These are commands for the target environment; they were **not run** during
Stage 1 implementation, at the user's request to skip tests and validation.

```sh
mpiexec -n 1 ./custatevec_bench --smoke-check
mpiexec -n 2 ./custatevec_bench --smoke-check --nqubits 8
```

The default is max(8, log2(P)+1) total qubits, with a hard limit of 20 total qubits
to keep the complete host-side inspection affordable. For multiple nodes, use
the site's launcher and place ranks on distinct GPUs across nodes. The smoke
check allocates a single distributed state, initializes |0>, applies a local
complex128 X gate, checks every amplitude and a double MPI norm reduction, swaps
a local/global index bit and reverses it when P>1, then restores |0>. It writes
only diagnostics to stderr and never emits benchmark CSV or timing rows.

A reported MPI, CUDA, cuStateVec, allocation, or argument error calls MPI_Abort
so peers do not remain in normal collective cleanup. Launcher timeouts are still
needed for process crashes, transport hangs, or failures that never return.

## Benchmark interface and extension points

Production defaults are N=31, repeats=128, warmup=0, seed=1, complex128 throughout,
and no gate fusion. Options accept unsigned decimal integers; seed accepts the
full uint64 range. N is restricted to 1..62 for signed 64-bit cuStateVec indices,
with separate checked byte arithmetic and actual GPU-capacity checks.

The eventual jobs run independently, including as separate scheduler jobs:

```sh
mpiexec -n 2 ./custatevec_bench --job hadamard --nqubits 31 --repeats 128 --warmup 0 --seed 1
mpiexec -n 2 ./custatevec_bench --job measure --nqubits 31 --repeats 128 --warmup 0 --seed 1
```

**Both commands fail explicitly in Stage 1**, before allocating the large state.
They cannot be used to obtain measurements yet.

Implement `Job` in `include/bench.hpp` and connect it through `make_job` in
`src/benchmark.cu`. `prepare` allocates reusable workspaces/descriptors;
`initialize` independently initializes each repetition; `execute` performs the
whole operation and completes its MPI requests. The harness resets mapping,
completes initialization, barriers, times with local MPI_Wtime, synchronizes the
whole GPU, stops the timer, then reduces durations with MPI_MAX. Measurement
probability work belongs inside execute. CSV formatting happens after timing.
Warm-ups have no output rows and do not change measured seed indices.

Only rank 0 writes benchmark CSV to stdout:

```text
job,iteration,nqubits,mpi_ranks,elapsed_seconds,measurement_bits
```

Iteration numbering starts at 1; measurement bits are empty for Hadamard and will
be ordered q[N-1]..q[0] for measurement. Metadata goes to stderr: versions, GPU
identities, rank mapping, explicit allocation bytes, seed, warm-up count, and
timing scope. Memory capacity checks use current free GPU memory after context
and handle creation, then query and account for communication and operation
workspaces outside repetitions. The sum of explicit buffers excludes internal
CUDA/MPI/library allocations, which reduce the free memory reported by CUDA.
