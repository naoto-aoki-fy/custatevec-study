# Distributed cuStateVec benchmark

Detailed benchmark setup and usage, moved from README. Historical implementation
notes below describe their original execution status; current evidence and
unrun GPU/MPI acceptance work are recorded in [VALIDATION.md](VALIDATION.md).

The implementation provides a C++17/CUDA/MPI runtime, a reusable benchmark timing
harness, independent Hadamard and full-register measurement benchmarks, and
opt-in untimed small-state checks.
The common contract is recorded in [SPEC.md](SPEC.md).
The separate [QCS compatibility library](qcs-library.md) builds with `make library`
and implements gates, measurement/reset, expectations, statevector export and events.
See [VALIDATION.md](VALIDATION.md) for execution limits.

## Build prerequisites

Use a 64-bit Linux environment with GNU Make, nvcc, a compatible host compiler,
CUDA, the classic cuStateVec library with distributed index-bit swap APIs, and
CUDA-aware MPI. MPI must support device-buffer communication both within and
between nodes. By default, mutually usable same-node swap peers are explicitly
registered with cuStateVec using CUDA IPC memory and events. Other pairs use the
CUDA-aware MPI communicator. No particular world-rank placement is required.
Each MPI process owns one GPU and one contiguous sub-state-vector.

Provide an **existing** configuration generated by
[nvccoptions](https://github.com/naoto-aoki-fy/nvccoptions#using-the-generated-configuration).
Its README was consulted for the Makefile design. No config.mk was supplied in
this workspace, so there was no generated configuration to inspect. The project
never generates or overwrites it and does not discover MPI wrapper flags itself.
Inspect the configuration from your target compiler/MPI environment before use.
Its `CFLAGS_VENDOR`, `LDFLAGS_VENDOR`, and `GENCODE_FLAGS` definitions are required;
any exported environment variables remain exported to build commands.

```sh
make CONFIG_MK=/path/to/config.mk CUSTATEVEC_ROOT=/path/to/cuquantum
```

Compilation and final linking both use `NVCC` (default
`nvcc --forward-unknown-to-host-compiler`), following nvccoptions' host-option
forwarding guidance. Compiler, MPI, and GPU architecture settings come from the
included configuration. Load the matching compiler environment before building.
Missing MPI headers and libraries must be resolved through that configuration,
not by substituting a separately detected wrapper.

Project and installation overrides are separate from the imported settings:

| Make variable | Default / purpose |
| --- | --- |
| `CONFIG_MK` | `config.mk`; external nvccoptions configuration |
| `NVCC` | `nvcc --forward-unknown-to-host-compiler`; CUDA compiler command |
| `PROJECT_FLAGS` | `-O3 -std=c++17` |
| `EXTRA_CPPFLAGS` | Additional preprocessor/include options |
| `EXTRA_NVCCFLAGS` | Additional nvcc options, including explicit `-Xcompiler` forwarding if needed |
| `EXTRA_LDFLAGS` | Additional link options; use `-Xlinker` for host linker options if needed |
| `CUSTATEVEC_ROOT` | `/usr/local/cuquantum` |
| `CUSTATEVEC_INCLUDEDIR` | `$(CUSTATEVEC_ROOT)/include` |
| `CUSTATEVEC_LIBDIR` | `$(CUSTATEVEC_ROOT)/lib`; set to `lib64` when appropriate |
| `CUSTATEVEC_CPPFLAGS` | Include flag from `CUSTATEVEC_INCLUDEDIR` |
| `CUSTATEVEC_LDFLAGS` | Library search path, runtime rpath, and `-lcustatevec` |

Header and nvcc presence errors have explicit messages. Compiler/linker errors
identify missing MPI/CUDA headers or libraries and incompatible APIs. For a
custom cuStateVec layout set the includedir/libdir variables; full flag overrides
must supply the corresponding include/search/link options. The dynamic loader
must also find the MPI implementation, CUDA runtime, and any communicator plugin.
`make clean` and `make help` work without configuration and never alter config.mk.

## Communicator and GPU assignment

The runtime infers the built-in Open MPI or MPICH communicator from `mpi.h`
macros. The selected cuStateVec communicator must match the application's MPI
ABI and the MPI used by the launcher. Use `--communicator openmpi` or
`--communicator mpich` for an explicit selection when headers cannot identify it.
Only select MPICH for an implementation with the compatible ABI supported by your
cuStateVec release. Use `--communicator external --communicator-library /path/to/mpicomm.so`
for other MPI implementations. Build that plugin from the samples accompanying
your cuStateVec release, against the **same MPI installation** as the application;
it wraps MPI_COMM_WORLD. Do not supply an arbitrary libmpi as an external plugin.

The optional `--communicator-library` names the library passed to
`custatevecCommunicatorCreate`. Built-in resolution/soname behavior varies by
cuStateVec release; consult the installed release's
[communicator API](https://docs.nvidia.com/cuda/cuquantum/latest/custatevec/api-reference/custatevec/index.html#custateveccommunicatorcreate).
Current documentation describes using already loaded MPI symbols for built-in
communicators. This project links the site's MPI directly through config.mk.
Newer standard-MPI-ABI communicator enums are deliberately not required by this
baseline; standard-ABI-only installations need a compatible external plugin.

Each process selects its assigned CUDA GPU and explicitly initializes its context
with checked `cudaSetDevice()` and `cudaFree(nullptr)` calls **before `MPI_Init()`**,
so MPI/UCX initialization starts with the intended context already initialized.
The small initialization helper uses no MPI calls, including on failure. Early
errors print to stderr and exit nonzero without `MPI_Abort()`; the launcher must
terminate other ranks if one exits before joining MPI. Even `--help` requires a
valid early GPU assignment.

Before MPI, local rank comes from `OMPI_COMM_WORLD_LOCAL_RANK` when present,
otherwise `SLURM_LOCALID`. Open MPI takes precedence because a surrounding Slurm
task's local ID may differ from the ranks launched by `mpiexec`. The Slurm fallback
requires a direct Slurm launch where each task corresponds to one MPI process;
it is not a reliable rank source for arbitrary nested launchers. No other MPI
implementation's environment variables are inferred. The selected variable must
contain only decimal digits and fit a nonnegative `int`; empty or malformed
values fail rather than falling back to another source.

With one visible GPU a process selects visible ordinal 0, even when its local
rank is greater than zero or unavailable. With multiple visible GPUs it selects
its launcher-provided local rank; a missing rank or a rank outside the visible
device count fails before MPI. For other launchers, expose one distinct GPU per
process through the scheduler or a launcher wrapper, or add support for a
documented process-local rank source before using multiple visible GPUs. Global
rank and physical GPU ordinals are never substituted for local rank. All CUDA
ordinals respect `CUDA_VISIBLE_DEVICES` and scheduler-enforced visibility.

After MPI starts, topology is still discovered with
`MPI_Comm_split_type(MPI_COMM_TYPE_SHARED)`. `Runtime` receives the early assignment
from `main`, checks any supplied local rank against the actual shared-node rank
(also for single-visible-GPU processes), verifies the device-selection policy
and current CUDA device, and reuses that device without calling `cudaSetDevice()`
again. A mismatch aborts through the existing MPI error path before GPU resource
setup. Stderr reports the early rank source, selected visible device, context
initialization result, and successful post-MPI assignment verification. These
messages are outside benchmark timing and do not change stdout CSV.

UUIDs are exchanged within the node to reject
duplicate assignments, including duplicate assignments hidden by per-rank device
visibility. A rank count must be a power of two, and `N > log2(P)`. Rank ordering
across nodes does not need to be contiguous. Set GPU visibility through the
launcher; do not oversubscribe GPUs.

## Explicit same-node P2P

`--p2p auto|off|required` defaults to `auto` and applies to all jobs and all
check modes:

| Mode | Behavior |
| --- | --- |
| `auto` | Attempt CUDA IPC memory/event imports for same-node swap peers; register a pair only after both directions succeed; otherwise use MPI with a stderr diagnostic |
| `off` | Skip explicit cuStateVec P2P registration; use the communicator path. MPI itself may still optimize transfers with CUDA IPC |
| `required` | Require explicit registration for all same-node pairs used by the selected workload; a world-wide decision aborts before timing if any is unavailable. Inter-node transfers continue through MPI |

The shared-node communicator exchanges world ranks and IPC handles. World rank
remains the sub-state-vector index, including non-contiguous node placement.
Only workload swap peers are imported: both Hadamard orders and their
asymmetric-state check use rank-XOR-one-bit peers, the smoke check uses rank XOR 1, and measurement has
no swap peers. P=1, measurement, and launches with no same-node swap pairs can
therefore use `required` successfully without any P2P registrations.

Unified addressing and IPC event support are checked on the assigned GPU;
memory/event export and import determine usable resources. No remote device
ordinal is used. A single visible GPU does not disable P2P: CUDA IPC memory
import can resolve an exporting GPU outside the importing process's visibility.
Unsupported IPC/peer access, peer limits, mapping failures, and OS IPC access
failures produce fallback diagnostics. Invalid arguments/handles, allocation
errors, and unrelated CUDA failures abort the world rather than silently falling
back. Driver or scheduler restrictions may still prevent imports.

Setup and registration occur before repetitions. Existing compute-before-swap
and transfer-before-gate waits remain inside each swap. Imports persist through
worker destruction; shutdown completes work, barriers, destroys workers,
barriers, destroys imported events/closes imported memory, then barriers before
freeing exported allocations and local events. A required-mode setup rejection
closes all imports before aborting. Other fatal errors use MPI_Abort rather than
collective cleanup. As with existing failures, launcher timeouts are needed for
crashes or transport calls that never return.

Stderr reports the requested mode, registered peer world ranks, fallback
reasons, and the existing rank/host/GPU UUID/PCI identity metadata. Successful
registration identifies explicit CUDA IPC P2P; it does not establish NVLink or
any particular physical interconnect. Transfer-workspace policy is configured
separately below; timing boundaries and CSV columns remain unchanged.

## Benchmark interface and extension points

Production defaults are N=31, repeats=128, warmup=0, seed=1, complex128 throughout,
and no gate fusion. Options accept unsigned decimal integers; seed accepts the
full uint64 range. N is restricted to 1..62 for signed 64-bit cuStateVec indices,
with separate checked byte arithmetic and actual GPU-capacity checks.

Jobs run independently, including as separate scheduler jobs:

```sh
mpiexec -n 2 ./custatevec_bench --job hadamard --nqubits 31 --repeats 128 --warmup 0 --seed 1
mpiexec -n 2 ./custatevec_bench --job hadamard-reverse --nqubits 31 --repeats 128 --warmup 0 --seed 1
mpiexec -n 2 ./custatevec_bench --job measure --nqubits 31 --repeats 128 --warmup 0 --seed 1
```

These commands select the implemented jobs in separate MPI invocations; they
are examples, not recorded execution results.

Workloads implement `Job` in `include/bench.hpp` and are connected through
`make_job` in `src/benchmark.cu`. `prepare` allocates reusable workspaces/descriptors;
`initialize` independently initializes each repetition; `execute` performs the
whole operation and completes its MPI requests. The harness resets mapping,
completes initialization, barriers, records a start CUDA event on the compute
stream, executes the operation, synchronizes the whole GPU, then records a stop
CUDA event on the compute stream. It waits for stop with `cudaEventSynchronize`,
reads milliseconds with `cudaEventElapsedTime`, converts to seconds, and reduces
rank-local durations with MPI_MAX. The timing-enabled pair is created once per
rank outside the loops and destroyed after the loops, separate from the
timing-disabled swap/P2P events. Elapsed GPU event-marker time may include host
submission gaps and MPI-related waits; it is not a sum of active kernel times. Measurement
probability work belongs inside execute. CSV formatting happens after timing.
Warm-ups have no output rows and do not change measured seed indices.

Only rank 0 writes benchmark CSV to stdout:

```text
job,iteration,nqubits,mpi_ranks,elapsed_seconds,measurement_bits
```

Iteration numbering starts at 1; measurement bits are empty for Hadamard and are
ordered q[N-1]..q[0] for measurement. Metadata goes to stderr: versions, GPU
identities, rank mapping, explicit allocation bytes, seed, warm-up count, and
timing scope. Memory capacity checks use current free GPU memory after context
and handle creation, then query and account for communication and operation
workspaces outside repetitions. The sum of explicit buffers excludes internal
CUDA/MPI/library allocations, which reduce the free memory reported by CUDA.

## Hadamard workloads (Stage 2)

Each repetition fully reinitializes the distributed state to |0> and resets the
logical-to-physical mapping to identity before timing. It applies H to logical
qubits q=0,1,...,N-1 for `--job hadamard`, or q=N-1,N-2,...,0 for
`--job hadamard-reverse`, using exactly N separate `custatevecApplyMatrix` calls on
every rank (31 at the production default). The explicit row-major matrix is
`(1/sqrt(2)) * [[1,1],[1,-1]]`, stored as complex128 and applied with FP64
computation, one target, and no controls. Gates are never fused; initialization
is not used as a substitute for the gate sequence.

Both jobs share initialization, workspace preparation, and gate application.
Reverse order refers to logical indices, regardless of their changing physical
positions. Their final logical states agree, but their swap sequences and timing
can differ. Both use the same swap resources and `--p2p auto|off|required` peer
policy (rank XOR each global-rank bit). CSV records the selected job name and
leaves `measurement_bits` empty for both orders.

When a logical target occupies a global physical bit, the deterministic policy
swaps that bit with **physical bit 0** using the distributed scheduler and swap
worker. Both affected logical owners' positions are updated. This remains valid
when bit 0 holds a logical qubit whose gate has already executed. The next gate
uses its target's current position. The final mapping is retained without a
restoration swap. All ranks follow the same schedule, including when only one
local bit is available.

The handle uses `Runtime::stream` for compute, including gates and state
initialization. A distinct nonblocking `transfer_stream_` is created only for distributed swaps with
P>1 and passed exclusively to the swap worker. Both streams belong to the
rank's assigned GPU. NVIDIA's
[stream contract](https://docs.nvidia.com/cuda/cuquantum/latest/custatevec/overview/index.html#using-cuda-stream-with-distributed-index-bit-swap-api)
requires a dedicated transfer stream because the worker synchronizes with its
peer independently of ordinary handle operations.

Each swap first synchronizes the compute stream, executes all worker batches,
then synchronizes the transfer stream before mapping updates or subsequent
gates. This prevents transfers from reading unfinished gate writes and gates
from accessing unfinished swap results. Worker execution manages communication;
its return alone is not assumed to complete GPU work. The final transfer-stream
wait follows NVIDIA's distributed-swap example. This relies on the selected
cuStateVec communicator and CUDA-aware MPI completing worker-owned requests
according to that API contract; CUDA stream synchronization does not itself
wait on arbitrary MPI requests. No additional per-swap MPI barrier is used.

These waits, swaps, communication, gates, and the harness's final device
synchronization remain inside the CUDA event-marker interval; durations still
use MPI_MAX across ranks. Initialization and workspace allocation remain outside
timing. Streams live across repetitions. Cleanup synchronizes the device and
barriers before destruction, destroys the worker before its transfer stream
and dependent buffers/event/communicator, then destroys both streams. All
errors use the existing MPI_Abort path rather than normal collective cleanup.

## Full-register measurement workload (Stage 3)

`--job measure --initial-state uniform|flat|zero|ghz` selects the input state;
`uniform` is the default. `flat` is an alias for `uniform` and is reported as
`initial_state=uniform`. Explicit `--initial-state` is rejected for Hadamard
and all check modes, including `--check-measure`, which checks all three states.
Invalid values are rejected.

Before every warm-up and measured repetition, a GPU kernel directly writes the
selected state in complex128, without applying gates:

| Initial state | Nonzero amplitudes at global indices | Possible outcomes |
| --- | --- | --- |
| `uniform` | Every amplitude is `exp2(-N/2) + 0i` | Any N-bit string |
| `zero` | Index 0 has amplitude 1 | All zeros |
| `ghz` | Indices 0 and `2^N - 1` have amplitude `1/sqrt(2)` | All zeros or all ones |

All other amplitudes are zero. Initialization follows the contiguous rank
layout: index 0 belongs to rank 0, and the last index belongs to rank P-1
(both belong to rank 0 for P=1). The global squared norm is 1. Initialization,
device completion, and the start barrier precede timing. Rank 0 reports
`initial_state=<value>` to stderr; the CSV schema is unchanged.

```sh
mpiexec -n 1 ./custatevec_bench --job measure --initial-state zero --nqubits 8 --repeats 4
mpiexec -n 2 ./custatevec_bench --job measure --initial-state ghz --nqubits 8 --warmup 2 --repeats 4
mpiexec -n 2 ./custatevec_bench --job measure --initial-state uniform --nqubits 8 --repeats 4
```

Defaults remain 128 independently initialized, separately timed measurements,
zero warm-ups, and complex128 storage with double probability calculations.

Inside each measured operation, `custatevecAbs2SumArray` computes the actual
local squared norm. After stream completion, MPI gathers one double per rank
to rank 0; no amplitudes are gathered. Rank 0 sums these masses and uses one
seed/repetition-derived draw to select a rank from half-open probability
intervals. Zero-mass ranks are skipped. The draw is scaled by the measured
global squared norm, so this path also handles nonunit input norms. A product
rounded to the interval's upper endpoint is clamped to the preceding double.

Rank 0 broadcasts the owner and the conditional draw within that rank's mass.
The owner calls `custatevecBatchMeasureWithOffset` once for all local bits
in descending physical qubit order (see [ordering and validation](measurement-order.md)),
using offset zero and its measured local squared norm for this conditional
distribution. This is the local part of one joint full-register measurement.
It queries the selected amplitude's actual squared magnitude using a full local
bit mask, then calls `custatevecCollapseByBitString` with that normalization.
This preserves the selected complex phase. Every other rank zeros its entire
sub-state-vector. The owner broadcasts the complete 64-bit physical outcome,
including its rank bits; all ranks translate it through the logical mapping.
Rank 0 formats exactly N binary characters, q[N-1] through q[0], after timing.

Draws use a SplitMix64 counter transformation of the uint64 seed and repetition
index, converting its top 53 bits to a double in [0,1). Measured indices start
at zero and warm-ups occupy the separate high-bit domain. Repetitions do not
reseed a generator to repeat one draw, and warm-ups do not change measured draws.

The default cuStateVec workspace is queried, capacity-checked, allocated, and
bound to the handle in `prepare`. Bit ordering, outcome storage, and the host
rank-mass buffer are also allocated there. Workspace and total explicit GPU
allocation sizes are reported to stderr. No application buffers or descriptors
are allocated in `execute`, and probability results are recomputed each time.
Probability computation, draw coordination, MPI communication, local
measurement, global collapse, normalization, and final device synchronization
all belong to the measured interval.

Optional deterministic checks for the target environment, **not run** here:

```sh
mpiexec -n 1 ./custatevec_bench --check-measure --nqubits 8
mpiexec -n 2 ./custatevec_bench --check-measure --nqubits 8
mpiexec -n 4 ./custatevec_bench --check-measure --nqubits 3
```

This separate mode defaults to max(8, log2(P)+1) qubits, caps N at 20, and emits
no benchmark CSV. Controlled draws include zero, exact interval boundaries,
and the largest double below one. An independent CPU cumulative reference
checks basis states on low/middle/high ranks, unequal rank and local masses,
zero-probability ranks, local probability gaps, and all three GPU initialization
methods. Each initialization is compared amplitude by amplitude across ranks,
and its global norm is reduced before measurement. The zero state must always
produce all zeros; controlled draws below and above 0.5 deterministically
exercise both GHZ outcomes. Each draw starts with fresh GPU initialization,
including after a collapsed state. The commands above cover P=1, P=2, and P=4;
at P=4 the GHZ case also exercises intermediate ranks with zero mass.
Fixtures include nonunit norms and complex phases. Every collapse checks the
complete local state on each rank, exactly one surviving global amplitude,
retained phase, global unit norm, and outcome agreement across all ranks.
These deterministic fixtures do not use a statistical sampling assertion.

## Independent launch scripts and cluster placement

The executable requires an explicit job selection. Each command below is one
invocation and produces its own CSV file. The scripts need Bash and default to
two ranks, N=31, 128 measured repetitions, no warm-ups, and seed 1:

```sh
bash scripts/launch-hadamard.sh > hadamard.csv 2> hadamard.log
bash scripts/launch-hadamard-reverse.sh > hadamard-reverse.csv 2> hadamard-reverse.log
bash scripts/launch-measure.sh > measure.csv 2> measure.log
```

Set `MPIEXEC` to one launcher executable, `NP_FLAG` to its rank-count flag
(default `-n`), `RANKS`, `BENCHMARK`, `NQUBITS`, `REPEATS`, `WARMUP`, and `SEED`
as needed. `COMMUNICATOR` and `COMMUNICATOR_LIBRARY` set the corresponding
benchmark options. Pass launcher arguments before `--` and benchmark arguments
after it. Arguments retain their boundaries; no environment value is evaluated
as shell code. Do not pass another `--job` option.

`P2P` sets `--p2p` for either launch script and defaults to `auto`. Benchmark
arguments after `--` can override it, for example:

```sh
P2P=off RANKS=2 bash scripts/launch-hadamard.sh > hadamard-off.csv 2> hadamard-off.log
P2P=auto RANKS=2 bash scripts/launch-hadamard.sh > hadamard-auto.csv 2> hadamard-auto.log
RANKS=2 bash scripts/launch-hadamard.sh -- --p2p required --nqubits 8 --repeats 2
```

Single-node examples assume Open MPI, two distinct visible GPUs, and no CPU
binding (replace the placement flags for other MPI implementations):

```sh
RANKS=2 bash scripts/launch-hadamard.sh --map-by ppr:2:node --bind-to none > hadamard.csv 2> hadamard.log
RANKS=2 bash scripts/launch-measure.sh --map-by ppr:2:node --bind-to none > measure.csv 2> measure.log
```

Multi-node examples assume Open MPI, passwordless/site-managed remote launch,
the same binary and libraries at the same paths on both hosts, and a hostfile
with two allocated nodes (one available slot each). Set `HOSTFILE` to that file.
Each node must expose its assigned GPU; the MPI installation must support the

## Distribution, CSV, and memory reference

For P=2^g world ranks, let L=N-g. World rank r owns physical indices
`r * 2^L + i`, `0 <= i < 2^L`. Local bits are the low L bits, rank bits the
high g bits, and bit 0 is least significant. Logical and physical positions
start equal each repetition; Hadamard localization updates both owners in the
mapping. No physical restoration is required. Measurement uses the complete
physical outcome and translates it to logical order before reporting it.

The default uniform measurement initialization uses amplitude `2^(-N/2)` on
every rank, giving global squared norm 1 and local squared norm 1/P, subject to
FP64 rounding. The zero state has mass 1 on rank 0. The GHZ state has mass 1/2
on ranks 0 and P-1 for P>1, or mass 1 on rank 0 for P=1. Other ranks have zero
mass. Sub-state-vectors are never normalized independently. The measured path
recomputes actual masses for every selected initial state.

| CSV column | Meaning |
| --- | --- |
| `job` | Selected `hadamard`, `hadamard-reverse`, or `measure` operation |
| `iteration` | One-based measured repetition; excludes warm-ups |
| `nqubits` | Total logical qubits across the distributed state |
| `mpi_ranks` | Number of world ranks sharing that state |
| `elapsed_seconds` | Maximum of rank-local CUDA event-marker intervals, converted from milliseconds to seconds |
| `measurement_bits` | Exactly N logical bits q[N-1]..q[0] for measurement; empty for Hadamard |

With `--job` selected and other options omitted, rank 0 writes one header and
128 data rows. MPI launcher output must not be merged into stdout. Capture
stderr separately. A nonzero exit status invalidates a partial output file.

State storage alone is `16 * 2^(N-g)` bytes per GPU, or `16 * 2^N` globally.
At N=31 this is 32 GiB globally: 32, 16, 8, or 4 GiB per GPU for P=1,2,4,8.
Add the job's gate or default measurement workspace. Distributed Hadamard and
smoke checks also need queried swap extra workspace and a common power-of-two
transfer buffer. Measurement and P=1 create no swap resources or transfer buffer.
Host measurement mass storage is 8P bytes per rank plus small bit arrays.
CUDA contexts, MPI transport, and library internals require further memory;
the state-size figures alone are insufficient for capacity planning. Allocation
checks use current free device memory. Transfer allocation races trigger the
collective shrinking retry described below; other allocation failures abort the
world. Workspace sizes and explicit totals are reported to stderr.

## Adaptive transfer workspace

`--transfer-buffer auto|min` defaults to `auto` and
`--transfer-buffer-fraction F` defaults to `0.95`. Fractions must be finite
and in `(0,0.95]`, including for skipped paths. Launch wrappers expose these as
`TRANSFER_BUFFER` and `TRANSFER_BUFFER_FRACTION`, or accept CLI options after
`--`. For example:

```sh
RANKS=4 NQUBITS=31 TRANSFER_BUFFER=auto TRANSFER_BUFFER_FRACTION=0.95 \
  scripts/launch-hadamard.sh -- --p2p auto
```

Preparation allocates the state, swap extra workspace, worker/scheduler,
communicator, events, CUDA IPC imports and job workspace before finalization.
Smoke reserves its gate workspace in the constructor; benchmark and Hadamard
check paths reserve theirs in `Job::prepare`. Measurement reserves its default
workspace and then finalizes without creating any swap resources. P=1 also
skips swap resources. No temporary transfer allocation is needed for setup.
All preparation, sizing collectives and allocation retries occur before checks
execute or warm-up/measured repetitions begin. Later workspace growth is rejected.

For each swap rank, finalization snapshots `F_r` with `cudaMemGetInfo` and
computes `budget_r = floor(F * F_r)`. The common budget is the world minimum;
the common worker requirement is the world maximum of reported minima.
`auto` selects the largest power of two within the common budget and at least
that requirement. `min` selects the smallest power of two satisfying the same
requirement, still within the budget. Neither policy exceeds the cap to meet
the minimum. Zero/insufficient budgets fail with byte counts. Integer arithmetic
uses a 128-bit intermediate for the fractional product; the default 0.95 is
exactly 19/20, and other fractions use their parsed binary64 value, bounded by
exactly 19/20. No fixed byte cap or state-vector-size cap is imposed.

The [NVIDIA transfer-workspace API reference](https://docs.nvidia.com/cuda/cuquantum/26.03.2/custatevec/api-reference/custatevec/index.html#custatevecSVSwapWorkerSetTransferWorkspace)
requires a power of two at least as large as the worker-reported minimum and
specifies no additional maximum or state-size constraint. This implementation
uses that contract; installed-library compatibility has not been validated.
The host compiler must support unsigned 128-bit integer arithmetic.

The percentage applies to **remaining free bytes after mandatory setup**, not
total device capacity or total application usage. Power-of-two rounding and the
least-memory rank can make allocation substantially lower than 95% of another
GPU's free memory. It is not a utilization target or a speed guarantee. Even
explicit P2P retains a valid transfer buffer for MPI fallback.

`cudaMemGetInfo` is a snapshot. On `cudaErrorMemoryAllocation` anywhere, all
ranks agree on failure, release successful allocations, barrier, and refresh
budgets. The next common candidate is the smaller of half the failed size and
the refreshed budget rounded down. This strictly decreasing sequence is bounded
by 64 attempts; it stops coherently if no size can satisfy the minimum. `min`
has no smaller valid fallback. Other CUDA errors abort immediately. Workers
receive the final buffer only after collective allocation success; all ranks
finish finalization before swapping.

Stderr includes policy/fraction, skipped status/reason, each budgeting snapshot,
local/common budgets, worker/common minima, initial/final sizes, retry count and
reduction reasons, post-allocation free bytes and explicit allocation totals.
Explicit totals include state, swap extra, transfer, gate and measurement
buffers, excluding CUDA/MPI/library internals and IPC imports. Those internals
already reduce the free-memory snapshot. Stdout CSV is unchanged.
